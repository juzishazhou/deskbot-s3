# 编译与烧录全流程（按 env 划分）

本工程有三个 PlatformIO 环境（`env`），产物和用途完全不同：

| env | 产物 | 用途 | 需要开发板 |
|---|---|---|---|
| `native` | 电脑上的可执行测试程序 | 跑纯逻辑单元测试、检查能否编译链接 | 否 |
| `module_test` | 测试固件 `.bin` | 分步验收 OLED / 红外 / 舵机 / 触摸，带串口命令 | 是 |
| `esp32-s3-devkitc-1` | 正式固件 `.bin` | 机器人本体 + 触摸/红外互动 + Wi-Fi 网页控制 | 是 |

所有命令都在工程根目录（`platformio.ini` 所在目录）执行。

## 一、环境准备

1. 安装 [PlatformIO Core](https://docs.platformio.org/en/latest/core/installation/)（本工程验证版本为 **6.2.0**）。
2. 首次编译会自动下载 `espressif32` 平台、Arduino 框架和 `lib_deps` 里的四个库（Adafruit SSD1306 / GFX / BusIO、Servo），需要联网。
3. 工程已固定 Flash 16MB、Octal PSRAM、`default_16MB.csv` 分区表，不用手动改板级选项。

> 本机特殊情况：系统 PATH 上的 `pio` 已损坏（PIO 5.2 + click 8.4 报 `resultcallback` 错误），
> 请改用 `C:\.platformio\penv\Scripts\platformio.exe`，并指定 `PLATFORMIO_CORE_DIR`：
>
> ```powershell
> $env:PLATFORMIO_CORE_DIR = 'C:\.platformio'
> & 'C:\.platformio\penv\Scripts\platformio.exe' --version   # 应输出 6.2.0
> ```
>
> 下文统一写 `pio`，本机执行时替换成上面这条命令即可。

## 二、env: native —— 电脑上的单元测试

不接开发板，验证 `src/logic/` 里的消抖、表决、优先级、归中计时、`millis()` 回绕、舵机限速。

```bash
# 跑全部单元测试（会自动编译）
pio test -e native

# 只检查 native 环境能不能编能链（入口在 src/native/stub_main.cpp）
pio run -e native
```

通过标准：输出 `12 test cases: 12 succeeded`，退出码 0。

说明：

- 该环境只编译 `src/logic/` 和 `src/native/`，不碰任何 Arduino 硬件代码，所以 `hw/` 有编译问题时这里不会报错——固件问题必须靠下面两个 env 发现。
- 跑测试时 `PIO_UNIT_TESTING` 已定义，`stub_main.cpp` 里的 `main()` 不会被编进来，入口由 Unity 提供。

## 三、env: module_test —— 测试固件（分步硬件验收）

第一次装机、换线、怀疑某个模块坏了时先烧这个。它不跑正式行为状态机，只用串口命令单独驱动每个模块，并且**不带 Wi-Fi**（省内存、也不会误开热点）。

```bash
# 1) 编译
pio run -e module_test

# 2) 烧录（用开发板上标 UART 的 USB 口）
pio run -e module_test -t upload

# 3) 打开串口（115200）
pio device monitor -e module_test
```

串口命令：

```text
help, status, stream on|off,
face normal|happy|confused|heart|listen|speak|sleep,
yaw <角度>, pitch <角度>,
center, servotest, stop
```

状态帧：`S,OLED,触摸,左红外,右红外,水平角度,俯仰角度,自检中`。

验收顺序：**OLED → 双红外 → 水平舵机 → 俯仰舵机 → 触摸**。舵机测试必须空载（先不装舵盘），舵机用独立 5V 并与开发板共地。
每个模块的具体判据见 [`接线与烧录验证指南.md`](接线与烧录验证指南.md)。

验收完烧回正式固件：

```bash
pio run -e esp32-s3-devkitc-1 -t upload
```

## 四、env: esp32-s3-devkitc-1 —— 正式固件

```bash
# 1) 编译（pio run 不带 -e 时就是它，因为是 default_envs）
pio run -e esp32-s3-devkitc-1

# 2) 烧录
pio run -e esp32-s3-devkitc-1 -t upload

# 3) 串口日志（会打印 Flash/PSRAM、引脚、热点地址）
pio device monitor -e esp32-s3-devkitc-1
```

烧录成功的日志会包含 `SUCCESS`，以及内存占用（当前约 RAM 14.0%、Flash 11.8%）。

上电后：

1. 串口出现 `Wi-Fi AP "Robot-Z" → http://192.168.4.1/`；
2. 手机连热点 `Robot-Z`（密码 `12345678`），浏览器打开 `http://192.168.4.1/`；
3. 页面 6 个按钮：表情（正常/开心/眨眼）、动作（点头/摇头/复位）；
4. 触摸、红外、串口照常工作，网页只是多了一个入口。

网页接口自检（同一热点下用手机浏览器或电脑）：

```text
http://192.168.4.1/api/face?type=happy
http://192.168.4.1/api/action?do=nod
```

正常返回 `{"ok":true,...}`；参数错返回 400 和 `{"ok":false,"error":"..."}`。

## 五、推荐的完整流程

**第一次装机**

1. `pio test -e native` —— 确认逻辑层没被改坏；
2. `pio run -e module_test -t upload` —— 逐模块验收；
3. 装舵盘（两轴回中后按 90° 装）；
4. `pio run -e esp32-s3-devkitc-1 -t upload` —— 整体验收 + 网页控制。

**日常改代码**

1. 改 `src/logic/` → 先 `pio test -e native`；
2. 改 `hw/` 或 `main.cpp` → `pio run`（正式固件）编过再上传；
3. 只调参数（`config.h`）→ 直接 `pio run -t upload`。

**发布前**

```bash
pio test -e native
pio run -e module_test
pio run -e esp32-s3-devkitc-1
```

三个都绿再烧板。

## 六、烧录失败排查

| 现象 | 处理 |
|---|---|
| `Timed out waiting for packet header` | 按住 BOOT → 点一下 RST → 松开 BOOT，再执行 upload |
| 反复超时 | 把 `platformio.ini` 的 `upload_speed` 从 `921600` 降到 `460800` 或 `115200` |
| 找不到串口 | 换一根数据线、换标 **UART** 的 USB 口；Windows 设备管理器看 COM 号 |
| 端口被占用 | 先关掉 `pio device monitor` 和串口助手，再上传 |
| 上传成功但没反应 | 看串口是否有启动横幅；没有就是没进 APP，重新上电一次 |
| 换 env 后行为不对 | 确认烧的是哪个固件：`module_test` 不跑行为状态机，也没有热点 |

## 七、清理与产物位置

```bash
# 产物
.pio/build/esp32-s3-devkitc-1/firmware.bin
.pio/build/module_test/firmware.bin

# 清掉某个 env 的编译缓存
pio run -e esp32-s3-devkitc-1 -t clean

# 擦除整片 Flash（会清掉分区表和 NVS）
pio run -e esp32-s3-devkitc-1 -t erase
```

`firmware.bin` 也可以手动用 `esptool.py` 烧，但正常流程用 `-t upload` 即可（它会自动带上 bootloader 和分区表）。
