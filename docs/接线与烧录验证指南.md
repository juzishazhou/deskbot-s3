# DeskBot-S3 接线、烧录与分步验证指南（纯 PlatformIO 版）

适用硬件：**ESP32-S3-DevKitC-1 N16R8**（16MB Flash + 8MB Octal PSRAM）。
本教程不使用网页工具，所有验证都在 VSCode + PlatformIO 的**串口监视器**里完成。

---

## 一、准备

### 1.1 硬件清单

| 器件 | 数量 | 说明 |
|---|---:|---|
| ESP32-S3-DevKitC-1 N16R8 | 1 | 16MB Flash + 8MB Octal PSRAM |
| SSD1306 OLED 128×64 | 1 | I²C，3.3V |
| SG90 舵机 | 2 | 水平 + 俯仰，**外部 5V 供电** |
| TTP223 触摸模块 | 1 | 3.3V |
| 红外避障模块 | 2 | 3.3V |
| 5V/2A 以上电源 | 1 | 仅给舵机，与开发板共地 |
| 470–1000µF 电解电容 | 1 | 并在舵机 5V 与 GND 之间 |
| 数据 USB 线 | 1 | 只能充电的线不能烧录 |

### 1.2 软件

1. 安装 VSCode。
2. 扩展商店安装 **PlatformIO IDE**。
3. 解压 `deskbot-s3.zip`。
4. 用 VSCode **打开整个 `deskbot-s3` 文件夹**（不要只打开某个 `.cpp` 文件）。

> 说明：本项目 `framework = arduino` 指的是 Arduino Core 代码框架，不是让你安装 Arduino IDE。所有操作都在 PlatformIO 里完成。

## 二、接线

改接线前**先断开 USB 和外部 5V**。

| 模块 | 模块引脚 | 开发板引脚 | 电源 |
|---|---|---|---|
| OLED | SDA | **GPIO8** | VCC → 3V3 |
| OLED | SCL | **GPIO9** | GND → GND |
| 水平 yaw 舵机 | 信号线 | **GPIO4** | 红线 → 外部 5V |
| 俯仰 pitch 舵机 | 信号线 | **GPIO5** | 地线 → 外部 GND |
| TTP223 | OUT | **GPIO7** | VCC → 3V3，GND → GND |
| 左红外 | OUT | **GPIO10** | VCC → 3V3，GND → GND |
| 右红外 | OUT | **GPIO11** | VCC → 3V3，GND → GND |

强制规则：

1. **舵机红线只能接外部 5V**，不能接开发板 5V 或 3V3。
2. 外部 5V 电源的 GND 必须与开发板 GND 相连（共地）。
3. OLED、TTP223、红外全部用 **3.3V**。
4. 避开 GPIO26–32（Flash）、33–37（PSRAM）、0/3/45/46（启动相关）。
5. 舵机电源端并联 470–1000µF 电容。

## 三、认识测试固件命令

测试固件入口是 `src/module_test.cpp`，环境名是 `module_test`。烧录后用串口监视器输入命令（每行一条，回车发送）。

| 命令 | 作用 |
|---|---|
| `help` | 显示全部命令 |
| `status` | 读取一次当前状态 |
| `stream on` | 每 200ms 自动输出一行状态 |
| `stream off` | 关闭自动输出 |
| `face normal` | OLED 普通表情，可换 `happy` / `confused` / `heart` |
| `yaw 90` | 水平舵机转到 90°，可换任意角度 |
| `pitch 90` | 俯仰舵机转到 90°，可换任意角度 |
| `center` | 两轴同时回 90° |
| `servotest` | 两轴依次执行 `90°→85°→95°→90°` 一轮自检 |
| `stop` | 停止自检并保持当前位置 |

状态帧格式：

```text
S,OLED,触摸,左红外,右红外,水平角度,俯仰角度,自检中
S,1,0,0,0,90,90,0
```

各字段含义：

| 字段 | 值 | 含义 |
|---|---|---|
| OLED | 1 / 0 | 屏幕是否就绪 |
| 触摸 | 1 / 0 | 是否正在触摸 |
| 左红外 | 1 / 0 | 左红外是否触发 |
| 右红外 | 1 / 0 | 右红外是否触发 |
| 水平角度 | 0–180 | 当前 yaw 角度 |
| 俯仰角度 | 0–180 | 当前 pitch 角度 |
| 自检中 | 1 / 0 | 是否正在执行 `servotest` |

## 四、第一次烧录（测试固件）

### 4.1 编译

在 VSCode 中打开终端（菜单 **终端 → 新建终端**），执行：

```bash
pio run -e module_test
```

第一次编译会自动下载工具链，需联网，等待显示 `SUCCESS`。

### 4.2 烧录

USB 线插开发板上标 **UART** 的口，执行：

```bash
pio run -e module_test -t upload
```

### 4.3 打开串口监视器

```bash
pio device monitor
```

按一下开发板 `RST`，应看到启动横幅：

```text
DESKBOT-S3-TEST 1.0
模块测试固件：OLED SDA=8 SCL=9，舵机 yaw=4 pitch=5
```

输入 `stream on` 回车，开始自动输出状态帧。

### 4.4 烧录失败处理

| 现象 | 处理 |
|---|---|
| 上传超时 | 确认 UART 口，不是 USB/OTG 口 |
| 仍超时 | 按住 **BOOT** → 点一下 **RST** → 松 RST → 松 BOOT，再上传 |
| 反复超时 | 把 `platformio.ini` 的 `upload_speed = 921600` 改成 `460800` 或 `115200` |
| 找不到串口 | 换数据线；安装 CP210x/CH340 驱动 |

## 五、逐模块验证

> 建议只接当前要测的模块，逐个通过后再接入下一个。改接线前断电。
> 串口监视器中输入命令后按回车发送。

### 5.1 OLED

1. 只接 OLED（SDA=8，SCL=9，3.3V）。
2. 烧录测试固件并打开串口监视器。
3. 输入 `status`，看状态帧第 1 个数字（OLED）。
   - **合格**：显示 `1`，表示已识别到屏幕。
   - **不合格**：显示 `0`。检查 SDA/SCL 是否接反、VCC 是否 3.3V。测试固件会每 2 秒自动重试。
4. 依次输入命令切换表情：
   ```text
   face normal
   face happy
   face confused
   face heart
   ```
   **合格**：四种表情清晰显示、双眼位置正确、切换不花屏。

### 5.2 双红外

1. 接入左红外（GPIO10）和右红外（GPIO11），3.3V 供电。
2. 输入 `stream on`，观察状态帧的第 3、4 个数字（左红外、右红外）。
3. 操作与期望：

| 操作 | 左红外 | 右红外 |
|---|---|---|
| 都不遮挡 | 0 | 0 |
| 只遮挡左边 | 1 | 0 |
| 只遮挡右边 | 0 | 1 |
| 两侧同时遮挡 | 1 | 1 |

**合格**：左右与实物一致。
**不合格**：
- 一直显示 `1`：把 `src/config.h` 中 `kIrActiveLow` 改成 `false`，重新编译烧录。
- 左右相反：交换 GPIO10 与 GPIO11 的接线。

### 5.3 水平舵机（GPIO4）

> **必须空载**：不装舵盘、不装纸壳头部。舵机用外部 5V 并共地。

1. 输入 `stream on`。
2. 依次输入：
   ```text
   yaw 85
   yaw 95
   yaw 90
   ```
   观察状态帧第 5 个数字（水平角度）是否依次变化。
3. 输入 `servotest`，执行一轮 `90°→85°→95°→90°` 自检。
   **合格**：动作平滑，无嗡鸣、卡住、发热或开发板复位。
   **异常**：立即输入 `stop`，然后断开舵机外部 5V。检查供电、共地、电容。

### 5.4 俯仰舵机（GPIO5）

同样空载测试：

```text
pitch 85
pitch 95
pitch 90
pitch 60
pitch 120
```

观察状态帧第 6 个数字（俯仰角度）。

**合格**：角度变化与命令一致，90° 时头部水平，60° 抬头、120° 低头。
**方向相反**：交换 `src/config.h` 中的 `kPitchUp` 与 `kPitchDown` 数值，不要强扭摇臂。

### 5.5 触摸（TTP223，GPIO7）

1. 输入 `stream on`，观察状态帧第 2 个数字（触摸）。
2. 手指触摸再松开，重复 5 次。

| 操作 | 触摸字段 |
|---|---|
| 未触摸 | 0 |
| 触摸中 | 1 |
| 松开 | 回到 0 |

**合格**：每次触摸状态变化一次，松开后回到 0，无抖动连触发。
**一直显示 1**：把 `src/config.h` 中 `kTouchActiveHigh` 改成 `false`，重新编译烧录。

## 六、整体验证（烧录正式固件）

全部模块通过后，烧录正式固件：

```bash
pio run -e esp32-s3-devkitc-1 -t upload
pio device monitor
```

按 `RST`，确认启动信息打印正常（Flash、PSRAM、CPU、引脚表）。

### 6.1 装配舵盘

1. 保持舵盘和纸壳头部拆下。
2. 上电后正式固件会自动让两轴回 90°。
3. 断电，按回中位置装回舵盘，再装纸壳头部。

### 6.2 整体行为验收

| 操作 | 期望行为 |
|---|---|
| 遮挡左红外 | 向左转头、抬头、开心眼 |
| 遮挡右红外 | 向右转头、抬头、开心眼 |
| 两侧同时遮挡 | 水平保持，继续抬头 |
| 移开遮挡 | 原地疑惑约 3 秒，然后平滑归中 |
| 短按触摸 | 水平停止、抬头、疑惑脸 |
| 长按触摸 800ms | 切换爱心眼，一次按住只触发一次 |
| 松手后 | 保持表情约 3 秒再归中；旧遮挡不会立刻重新接管 |
| 空闲 | 每 2.8–6.2 秒自动眨眼一次 |

**合格**：所有行为符合上表，舵机无持续嗡鸣、无异常复位。

## 七、调试辅助手段

1. **启动信息**：正式固件会打印 Flash、PSRAM、CPU 主频和引脚表，用于确认硬件配置。
2. **临时加日志**：在代码里用 `Serial.printf("yaw=%d pitch=%d\n", yaw, pitch);`，不要在中断里打印。
3. **崩溃定位**：`platformio.ini` 已启用 `esp32_exception_decoder`，重启后把 `Backtrace:` 一段贴出来即可看到出错函数。
4. **纯逻辑测试**（不需要开发板）：
   ```bash
   pio test -e native
   ```
   覆盖触摸消抖、长按、红外表决、行为优先级、归中计时、`millis()` 回绕、舵机限速限位。
5. **改参数后重新验证**：角度、电平、时间都在 `src/config.h`，改完重新 `pio run -e module_test -t upload`。

## 八、常见问题

| 现象 | 检查 |
|---|---|
| 上传超时 | UART 口、BOOT+RST、降低 `upload_speed` |
| OLED 不亮 | SDA=8/SCL=9 是否接反；VCC 必须 3.3V |
| 舵机抖动或复位 | 舵机是否独立 5V、是否共地、是否加电容 |
| 转头方向反 | 交换 `kYawLeft` 与 `kYawRight` |
| 抬头方向反 | 交换 `kPitchUp` 与 `kPitchDown` |
| 触摸一直触发 | `kTouchActiveHigh` 改成 `false` |
| 红外一直触发 | `kIrActiveLow` 改成 `false` |
| 上电反复重启 | 是否误接 GPIO0/3/45/46 或 Flash/PSRAM 引脚 |
